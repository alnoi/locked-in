# Порядок задач

Порядок задач общий для аккаунта, списков и фильтрованных дочерних досок. Порядок самих списков остаётся локальным. Завершённые сохраняют прежнюю сортировку от новых к старым, их ручная перестановка запрещена.

- `GET /api/v1/task-order` → `taskIDs`, `revision`; без сохранённого порядка revision=0, задачи идут по createdAt/id.
- `PUT /api/v1/task-order` принимает `taskIDs` и необязательный `initializeOnly`. Переданные задачи заменяют только свои позиции; скрытые задачи сохраняют позиции. Чужие и удалённые ID не принимаются. Задачи, появившиеся позже, добавляются в конец.
- Таблица `task_orders` принадлежит owner_id, запись сериализована общей транзакцией и advisory-блокировкой владельца. При одновременной перестановке одинаковых задач действует последний принятый сервером порядок.
- Apple-клиент хранит перестановку вместе с офлайн-кэшем. Она отправляется после создания/изменения задач, без блокировки интерфейса. UUID версии защищает новые перестановки от старого подтверждения.
- Существующий TaskOrderPreferences импортируется первым подключившимся устройством только при revision=0; initializeOnly не перезаписывает уже установленный порядок. Офлайн-кэш прежних версий читается без taskOrder.
- Обновление открытого второго устройства происходит при обычной синхронизации (до 30 секунд), возврате в приложение или ручном обновлении; ожидающая отправки очередь повторяется каждые 5 секунд. Локальный режим без сервера остаётся локальным.
