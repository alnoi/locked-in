# Аккаунты

- Логин: 3–32 латинских символа, цифры, `_ . -`; регистр не учитывается. Пароль: от 8 символов, максимум 256 байт UTF-8.
- Регистрация создаёт отдельного пользователя и пустую общую доску в одной транзакции.
- Пароли — Argon2id с отдельной солью; сессии — случайный Bearer-токен на 30 дней, в БД только его SHA-256. Выход отзывает текущую сессию.
- API: POST `/api/v1/auth/register`, `/auth/login`, `/auth/logout`; GET/PATCH `/api/v1/me`. Полный контракт — `backend/api/service/local_tracker/openapi.yaml`.
- Все задачи, проекты, доски, списки, теги и заметки фильтруются по владельцу из проверенной сессии; идентификатор пользователя клиент не назначает.
- Аватарка необязательна: без эмоджи показывается стандартный силуэт. В регистрации и профиле нажатие на всю строку открывает встроенный выбор эмоджи; поля ручного ввода нет. Выбранную аватарку можно убрать через контекстное меню строки.
- Токены приложения хранятся в Keychain; пароль используется только для входа/регистрации. На Mac общий доступ main/widget настроен ACL; на iOS — существующей App Group.
- Офлайн-очередь и кэш отдельные для каждого адреса сервера и пользователя. При выходе очередь остаётся на устройстве, доступна после нового входа тому же пользователю.
- Выход и истечение сессии скрывают данные, очищают виджеты и локальные уведомления. Настройки, порядки и история отмены изолированы между аккаунтами.
- Миграции 00015/00016 добавляют поля пользователя и сессии, не переписывая прежние записи. 00017 разрешает пустую аватарку, сохраняя выбранные ранее эмоджи.

Привязка старых данных выполняется только администратором на хосте бэкенда: после резервной копии БД передать `CredentialsIn` (Username, Password, TimeZone, AvatarEmoji) JSON через stdin команды `go run ./cmd/claim_profile`, с окружением из `.env`. Команда переименовывает существующего `LOCAL_USER_NAME`, задаёт хеш пароля и сохраняет прежний UUID, поэтому связи задач не меняются. Не передавать пароль аргументом командной строки и не сохранять его в Git.

Существующие архивы Apple-клиента сохраняются. Их копирование в новый аккаунт разрешено только при совпадении UUID пользователя. Порядки списков/задач и локальные настройки прежнего владельца переносятся один раз.

Регистрация новых аккаунтов и работа профиля выполняются на выбранном бэкенде. Переключение сервера не переносит данные между базами. Почта, восстановление пароля и двухфакторная проверка пока не реализованы.
