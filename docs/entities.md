# Сущности первой версии

- Пользователь: ID, имя, часовой пояс, дата создания. Пока один локальный пользователь без регистрации.
- Доска: ID, владелец, название, родитель, фильтр выполнения, теги фильтра; общая доска защищена от удаления.
- Список: ID, владелец, название, основная доска-владелец, общая позиция.
- Задача: ID, владелец, название, описание, выполнение, список, родитель, дедлайн, планирование, теги.
- Тег: ID, владелец, название, необязательный цвет.
- Комментарий: ID, владелец/автор, задача, текст, даты создания и изменения.
- Связи task_tags и board_tags хранят теги задач и фильтры досок соответственно.

## Доски и списки

Общая доска объединяет списки всех основных досок и входящие задачи без списка.
Обычная основная доска владеет своими списками. Дочерняя доска наследует списки родителя и фильтрует задачи внутри них.
Фильтры всех предков объединяются через AND; все выбранные теги должны присутствовать у задачи.
Списки, включая пустые после фильтрации, сохраняют исходные ID и названия. Задачи не копируются.
Противоречащие условия выполнения дают пустую выборку. Циклы досок запрещены.
Задача принадлежит максимум одному списку; без списка находится во входящих.
У каждой доски два вида: списки строками или столбцами. Выбор хранится локально для каждой доски.
Общая доска по умолчанию отображается столбцами, остальные — строками.
Порядок списков меняется перетаскиванием, хранится локально на устройстве по источнику данных и пользователю, сохраняется после перезапуска и одинаков для родителя и потомков. Положение входящих тоже хранится локально и меняется перетаскиванием.
Доску нельзя удалить с дочерними досками или списками; список нельзя удалить с задачами.

## Задачи

Из пользовательских полей обязательно только название. Выполнение по умолчанию false.
Проект — задача с дочерними задачами; отдельного типа project нет.
Максимум два уровня: родитель → дочерние задачи. Циклы запрещены, в том числе при конкурентных запросах.
Родитель и дети выполняются независимо. Задачи с детьми сначала нужно освободить от дочерних связей перед удалением.
Список, теги и даты детей независимы от родителя; автоматически не наследуются.
Дедлайн: либо deadlineDate (YYYY-MM-DD), либо deadlineAt (RFC3339). Оба одновременно запрещены.
Планирование: один plannedAt (RFC3339), независимо от него durationMinutes.
Продолжительность можно задать без старта; допустимый диапазон в БД — 1…525600 минут.
Точные моменты хранятся в timestamptz; дата без времени хранится в date.
Календарная выборка использует пересечение с полуоткрытым интервалом [from,to).
Старт без продолжительности отображается как точка во времени.

## Изменения и удаление

PATCH меняет переданные поля. Очистка optional-поля: clear<Field>: true; очистка тегов: tagIDs: [].
Явный null и неизвестные поля запроса отклоняются.
Удаление сущностей мягкое. Используемый тег удалить нельзя; удалённые задачи и их комментарии скрыты.
Повторения, совместный доступ, регистрация и синхронизация устройств — следующие этапы.

Напоминание: режим none/notification/alarm и интервал 0–10080 минут до события хранятся в задаче. Событие — начало в календаре, иначе точный дедлайн, иначе дата дедлайна с часом из локальных настроек (по умолчанию 10:00). Для будильника требуется точное время. Завершение, удаление и выключение отменяют будущий сигнал.
