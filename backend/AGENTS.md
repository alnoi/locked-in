# TrackIt — backend

## Границы
- Делай только запрошенное; дополнительные функции и изменения согласовывай.
- Коммиты и отправку на GitHub делай только по запросу.
- Поддерживай этот файл коротким; подробности храни в ../docs/.

## Структура и архитектура
- Этот каталог — Go-бэкенд с PostgreSQL; Apple-клиент находится в ../apple/.
- Бэкенд — модульный монолит: identity и tracker. Gin, pgx/v5, Goose, oapi-codegen.
- models — данные и простая валидация; domain — чистые правила; usecase — сценарии и транзакции.
- HTTP и PostgreSQL — крайние слои с мапперами; зависимости собираются в internal/app/.
- Порты объявляет потребитель; репозитории получают транзакцию через context.
- Контракт: api/service/local_tracker/openapi.yaml; generated/ вручную не менять.

## Предметная область
- В задаче обязательно только название; список, теги, родитель и даты необязательны.
- Проект — задача с детьми. Только два уровня: родитель → задачи; циклы запрещены.
- Доска содержит списки, список — задачи. Дочерняя доска фильтрует задачи родителя, сохраняя его списки.
- Общая доска объединяет все списки и входящие; обычная основная доска владеет своими списками.
- Унаследованные фильтры тегов и выполнения объединяются через AND.
- Задача принадлежит одному списку или входящим; поля детей независимы от родителя.
- Дедлайн: дата без времени либо точный момент. Планирование: один старт и независимая длительность.
- Комментарии — отдельные записи. Данные личные, ограничены owner_id; FK включают владельца.
- Проверка графов и запись — одна транзакция с advisory-блокировкой пользователя.
- Удаление мягкое; общая доска, используемые теги, непустые доски и задачи с детьми защищены от удаления.
- Аккаунты: логин/пароль, Argon2id (64 MiB, t=3, p=1), непрозрачные сессии на 30 дней; в БД только SHA-256 токена. /auth/register и /auth/login открыты с лимитом попыток, остальное API требует Bearer. Actor берётся из сессии каждого запроса; scope owner_id сохраняется во всех репозиториях. Бэкенд слушает только loopback. HTTPS снаружи обслуживает отдельный Nginx; SERVER_TRUSTED_PROXIES задаётся только для loopback-прокси, он перезаписывает X-Real-IP и X-Forwarded-For.

- Удаление списка атомарно переносит все его живые задачи (включая завершённые и скрытые фильтром) во входящие, сохраняя проектные связи, затем мягко удаляет список в общей транзакции/блокировке пользователя.
- Порядок списков остаётся локальным. Порядок задач синхронизируется через GET/PUT /task-order: task_orders по owner_id, task_ids + revision. Частичная перестановка сохраняет слоты скрытых задач; неизвестные/чужие/удалённые ID отвергаются атомарно. Запись под общей owner-блокировкой; initializeOnly импортирует локальный порядок только до первой записи. Подробнее ../docs/task-order.md.

- Напоминания задачи синхронизируются: none → notification → alarm; интервал — минуты до события.
- Приоритет: plannedAt → deadlineAt → deadlineDate. Будильник требует точного времени; дата без времени — уведомление в 10:00 (час настраивается локально).

- POST /tasks принимает опциональный стабильный id: повтор для той же задачи/владельца возвращает запись без перезаписи, чужой/удалённый ID — конфликт. Это защита от дублей офлайн-очереди Apple-клиента.

## Проверки и запуск
- Миграции: одна таблица на файл, NNNNN_create_<table>.sql, Up/Down; индексы рядом с таблицей.
- Применённые миграции не переписывать без явно запрошенного и проверенного перехода.
- Из этого каталога: make fmt, make lint; для правил — make unit-test.
- SQL/API: TEST_DATABASE_URL=… make integration-tests; пакеты выполнять последовательно.
- Тесты используют временные схемы; рабочую базу ради тестов не очищать.
- Локальный запуск: make up, make run. При запуске bin/locked_in обязательно сначала пересобирать; старый бинарник не знает новых маршрутов. .env и локальные артефакты не коммитить.
- Подробности: ../docs/entities.md, ../docs/architecture.md, README.md.

- Пустой проект: tasks.is_project / API isProject. Проект определяется флагом или наличием детей (совместимость старых данных); преобразование выставляет флаг без создания подзадачи, расформирование снимает флаг после отделения детей.

- При создании подзадачи или переносе в другой проект теги проекта добавляются к собственным тегам без дублей (на клиенте, включая офлайн, и на сервере). Это разовое копирование: последующие правки тегов независимы.

- POST /{tasks,boards,lists,tags,comments}/{id}/restore восстанавливает запись для Cmd+Z в транзакции с проверкой владельца и валидацией связей; ID/createdAt сохраняются. Повтор безопасен. PATCH tasks: inheritProjectTags=false применяется клиентом для точного возврата предыдущих тегов при отмене перемещения.

- CI/CD: .github/workflows/backend.yml — Docker build в PR, публикация GHCR и автодеплой main на Linux/amd64. Production Compose/deploy.sh в ../deploy/production/, серверная папка ~/trackit; контейнер track-it-backend, API только loopback через host network. Деплой по digest, pg_dump перед миграциями, healthcheck 204, rollback образа/Compose; БД автоматически не откатывать. Детали ../docs/deployment.md.

- identity: регистрация транзакционно создаёт пользователя, его общую доску и сессию. PATCH /me меняет эмоджи; POST /auth/logout отзывает текущую сессию. cmd/claim_profile читает JSON из stdin и привязывает старого LOCAL_USER_NAME к аккаунту без смены ID; из HTTP эта операция недоступна. Пароли/токены в логах и документации не сохранять.

- Ошибки API: только apperr.WriteError и белый каталог публичных code/status/message. Поля Message/Status входящей ошибки не отдавать; неизвестные коды и технические ошибки → internal_error с обращением в поддержку, детали только в серверном логе. Вход различает user_not_found (логин не найден) и wrong_password (неверный пароль), оба HTTP 401; регистрация возвращает известные коды валидации.

- Баг-репорты: feedback, POST /api/v1/bug-reports, доступен также без аккаунта (ограничение по IP); проверенная сессия задаёт owner_id, клиент его не передаёт. Описание обязательно, PNG/JPEG опционален, до 512 KiB; текст и байты хранятся в bug_reports. Клиентский UUID делает повтор отправки идемпотентным в пределах автора. Публичного чтения вложений/отчётов нет.
