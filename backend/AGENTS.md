# Locked In — backend

## Границы
- Делай только запрошенное; дополнительные функции и изменения согласовывай.
- Коммиты и отправку на GitHub делай только по запросу.
- Поддерживай этот файл коротким; подробности храни в ../docs/.

## Структура и архитектура
- Этот каталог — Go-бэкенд с PostgreSQL; Apple-клиент находится в ../apple/.
- Бэкенд — модульный монолит: identity и tracker. Gin, pgx/v5, Goose, oapi-codegen.
- models — данные и простая валидация; domain — чистые правила; usecase — сценарии и транзакции.
- HTTP и PostgreSQL — крайние слои с мапперами; зависимости собираются в internal/app/.
- Порты объявляет потребитель; репозитории получают транзакцию через context.
- Контракт: api/service/local_tracker/openapi.yaml; generated/ вручную не менять.

## Предметная область
- В задаче обязательно только название; список, теги, родитель и даты необязательны.
- Проект — задача с детьми. Только два уровня: родитель → задачи; циклы запрещены.
- Доска содержит списки, список — задачи. Дочерняя доска фильтрует задачи родителя, сохраняя его списки.
- Общая доска объединяет все списки и входящие; обычная основная доска владеет своими списками.
- Унаследованные фильтры тегов и выполнения объединяются через AND.
- Задача принадлежит одному списку или входящим; поля детей независимы от родителя.
- Дедлайн: дата без времени либо точный момент. Планирование: один старт и независимая длительность.
- Комментарии — отдельные записи. Данные личные, ограничены owner_id; FK включают владельца.
- Проверка графов и запись — одна транзакция с advisory-блокировкой пользователя.
- Удаление мягкое; общая доска, используемые теги, непустые доски/списки и задачи с детьми защищены от удаления.
- Пока один локальный пользователь без регистрации; сервер слушает только loopback.

- Порядок списков хранится только на устройстве по источнику данных и пользователю, общий для родителя и дочерних досок; сохраняется после перезапуска.

- Напоминания задачи синхронизируются: none → notification → alarm; интервал — минуты до события.
- Приоритет: plannedAt → deadlineAt → deadlineDate. Будильник требует точного времени; дата без времени — уведомление в 10:00 (час настраивается локально).

## Проверки и запуск
- Миграции: одна таблица на файл, NNNNN_create_<table>.sql, Up/Down; индексы рядом с таблицей.
- Применённые миграции не переписывать без явно запрошенного и проверенного перехода.
- Из этого каталога: make fmt, make lint; для правил — make unit-test.
- SQL/API: TEST_DATABASE_URL=… make integration-tests; пакеты выполнять последовательно.
- Тесты используют временные схемы; рабочую базу ради тестов не очищать.
- Локальный запуск: make up, make run. .env и локальные артефакты не коммитить.
- Подробности: ../docs/entities.md, ../docs/architecture.md, README.md.
