## Архитектура и модель
- SwiftUI, общий Planner.xcodeproj/scheme Planner для macOS и iPhone.
- Packages/LockedInKit: Domain — модели/правила; Data — сеть/хранение; UI — экраны/AppModel; LockedInActivity — общие Live Activity атрибуты. LockedInWidgetUI — виджеты; LockedInWidgets — общая macOS/iOS extension с Today/Calendar и iOS Live Activity.
- Go API: ../backend; контракт: ../backend/api/service/local_tracker/openapi.yaml. Mac/симулятор: localhost:8080; физический iPhone пока локальный.
- Сервер и локальный JSON — отдельные источники, не смешивать. Серверный режим: OfflineTaskRepository хранит snapshot + очередь задач атомарно в sync_<источник>.json; создание/правки/завершение/удаление работают без сети. Списки, доски, теги и комментарии — онлайн: при попытке без связи показывать ошибку «Для этого действия нужна связь с сервером», не блокировать кнопку только из-за офлайна. Старые SwiftData/локальные данные не удалять и не сбрасывать.
- Проекты в TaskReorderGroup отображаются общей карточкой: родитель + видимые по фильтру дети, один drag по ID родителя. TaskProjectGrouping задаёт корень и список проекта; drag переносит всю группу. ПКМ подзадачи действует только на неё; перенос в список отделяет её от проекта. «Переместить в проект» объединяет задачу с существующим проектом и задаёт его список, не допускает третьего уровня.
- Меню «…» списка в строках/столбцах: «Изменить» и «Удалить список». Удаление переносит все задачи во входящие; Snapshot.receive сразу снимает listID, OfflineTaskRepository также снимает ссылку в pending/base, чтобы очередь не возвращала удалённый список. Системные входящие не удаляются.
- Доска содержит списки; дочерняя доска фильтрует задачи, сохраняя исходные списки. Проект — задача с детьми, максимум два уровня.
- Обязательно только название задачи. Дедлайн — дата или точный момент; планирование — один старт и независимая длительность.
- Вид доски локальный: общая по умолчанию столбцы, остальные строки.
- listOrderIDs в AppModel — наблюдаемый общий порядок списков; при смене boardID сбрасывать drag preview.
- «Завершённые»: newestCompletedFirst в TaskReorderGroup сортирует задачи/подзадачи по updatedAt убыванию (отдельного completedAt в модели пока нет), обходя локальную ручную сортировку; drag по-прежнему запрещён.
- Порядок списков и задач локальный по источнику/пользователю, общий для родительских/дочерних досок, сохраняется после перезапуска. Фильтрованная перестановка сохраняет позиции скрытых задач.

- Офлайн-синхронизация: стабильный клиентский UUID задачи (POST id, повтор не создаёт дубль), версии очереди защищают новые правки от старого ACK. TaskSyncMerge сохраняет неизменённые локально серверные поля; при конфликте одного поля локальная правка приоритетна. Красный PendingSyncBadge появляется через 1 секунду ожидания ACK; быстрые сохранения не мигают. Адрес сохраняется независимо от доступности/валидности; отдельная кнопка ping только проверяет API, справа success/fail, настройки не меняет. Повтор каждые 5 сек при очереди/офлайне, обычно 30 сек; перед отправкой проверяется пользователь.

Конфетти DayCompletionCelebration — при фактическом завершении последней plannedAt-задачи сегодня, один раз в день/источник; удаление/перенос не триггер. DayPlan считает все plannedAt на день, включая задачи с просроченным дедлайном. Рабочие часы локальны (WorkdayPreferences, 09:00–21:00, конец позже начала). WorkdaySummaryScheduler ставит до трёх одноразовых системных итогов ближайших запланированных дней, обновляет количество/отменяет при завершении, не дублирует доставленный итог; делегат уведомлений остаётся TaskAlertScheduler.

- Пустой проект: tasks.is_project / API isProject. Проект определяется флагом или наличием детей (совместимость старых данных); преобразование выставляет флаг без создания подзадачи, расформирование снимает флаг после отделения детей.

- Cmd+Z: ActionHistory хранит до 100 действий текущего источника/пользователя на время запуска. Текстовый ввод отменяется нативно; задачи, коллекции, удаление и локальный порядок — обратными операциями через обычные репозитории. UndoGrouping объединяет проекты/drag в один шаг; виджетные завершения не записываются. При частичной ошибке остаются только невыполненные обратные операции. Удалённые записи восстанавливаются с исходными ID; очередь задач хранит restoring и восстановленные комментарии.

- Не передавать наблюдаемый AppModel.snapshot как inout в функции с UserDefaults.set: синхронное уведомление настроек вызывает SwiftUI-чтение snapshot и Swift exclusivity crash. Порядок применять к локальной копии, затем присваивать snapshot.

- Cmd+P в открытой существующей задаче переключает планирование: снимает plannedAt, сохраняя длительность, либо сохраняет черновик и планирует на сейчас на 60 минут с переходом в календарь. Cmd+Shift+Backspace остаётся снятием планирования; Cmd+Shift+P — переключением проекта.
